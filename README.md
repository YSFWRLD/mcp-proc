# Procurement MCP Server

An [n8n](https://n8n.io) workflow that exposes a small procurement toolkit over the
Model Context Protocol (MCP), backed by a single Google Sheet.

Point any MCP client (Claude, or anything else that speaks MCP) at the endpoint and it
gains four tools for logging purchase requests and picking suppliers.

## Tools

| Tool | Type | What it does |
|---|---|---|
| `create_rfq` | Google Sheets (append) | Logs a Request For Quotation as a row in the `RFQs` tab and returns the written row. |
| `list_rfqs` | Google Sheets (read) | Reads back every RFQ logged so far. |
| `find_suppliers` | Google Sheets (read) | Returns approved suppliers from the `Suppliers` tab, filtered by spend category. |
| `recommend_supplier` | Code tool | Ranks candidate suppliers with a weighted score and recommends one, with a rationale and full score breakdown. |

Intended flow: `create_rfq` → `find_suppliers` → `recommend_supplier`.

## The scoring model

`recommend_supplier` scores each candidate across four dimensions, min-max normalised
across the candidate set:

| Dimension | Weight | Direction |
|---|---|---|
| Unit price | 0.40 | lower is better |
| Lead time | 0.25 | lower is better |
| On-time delivery rate | 0.20 | higher is better |
| Rating | 0.15 | higher is better |

It also flags candidates whose `min_order_qty` exceeds the requested quantity, and
those with an on-time rate below 90%.

**Known limitation:** min-max normalisation means the cheapest candidate always
receives the full price weight and the most expensive always receives zero, regardless
of how wide the actual spread is. With a tight price range this overweights trivial
differences. If that matters for your data, switch to normalising against an absolute
reference (e.g. budget per unit) instead of the candidate set.

## Sheet schema

The workflow expects one Google Sheet with two tabs.

**`Suppliers`**

```
supplier_id, name, category, country, unit_price, currency,
lead_time_days, min_order_qty, rating, on_time_rate, contact
```

`category` must match exactly what callers pass to `find_suppliers` — the filter is an
exact string match, so trailing spaces or casing differences will silently return
nothing.

**`RFQs`**

```
rfq_id, created_at, requester, item, category, quantity, unit,
needed_by, budget_max, notes, status
```

`rfq_id`, `created_at` and `status` are generated by the workflow, not supplied by the
model. Everything else comes from the caller.

## Setup

1. Create the Google Sheet with the two tabs and header rows above.
2. Import `workflow.json` into n8n.
3. Open each Google Sheets node and reconnect your own Google Sheets OAuth2
   credential — the credential ID in the export is a placeholder.
4. In the same nodes, set **Document** to your own sheet
   (`YOUR_GOOGLE_SHEET_ID` in the export is a placeholder).
5. Publish the workflow. The MCP endpoint is then served at
   `https://<your-n8n-host>/mcp/procurement`.
6. Add that URL as a custom MCP connector in your client.

## Security note

The MCP trigger in this export has **no authentication configured**. Anyone who knows
the endpoint URL can call every tool, including `create_rfq`, which writes to your
sheet. Before using this anywhere real, open the MCP Server Trigger node and set an
authentication method (Bearer or header auth).

## Known issues

- **No auth on the MCP trigger** (see above).
- **`rfq_id` collisions.** IDs are timestamp-based to the second
  (`RFQ-yyyyMMdd-HHmmss`). Two RFQs raised in the same second would collide. A counter
  derived from the sheet's row count would be stricter.
- **Hardcoded category list.** The `find_suppliers` category description enumerates the
  valid categories. Add a category to the sheet and that description goes stale.
- **`unit` and `quantity` overlap.** `quantity` is a number and `unit` is a separate
  free-text field; nothing validates that they agree.

## Status

Prototype. The tool contracts work and the scoring logic is sound, but the auth gap
above means this is not production-ready as-is.
